# Frontend security controls are defense in depth; Backend must validate and audit authoritatively

Evidence uploads and exports touch Tier 2 data (see the `Sensitivity Tier` term in `CONTEXT.md`) — a citizen's identity, inspector findings, violation and sanction details. Backend exposes generic `/evidence` endpoints and now validates file bytes against the declared MIME type, enforces a 10 MB limit, and strips Exif, XMP, and comments from understood JPEG, PNG, and WebP files. It stores PDFs and image files with unrecognized container structure unchanged, and it does not scan for malware. No Tier-2 read/write audit exists; Backend explicitly deferred that work outside the current TPO delivery. No bulk/file export endpoint exists; aggregate indicator endpoints are not record exports, so no export allowlist is exercised today. This decision extends the posture in [ADR-0005](0005-m6-backend-is-the-sole-authorization-authority.md): frontend controls are not authoritative, and remaining security exclusions need an explicit release disposition.

Concretely: the frontend restricts file selection by declared type and size for usability; it does not re-encode image bytes or remove metadata. The current UI accepts PDF, which Backend stores without cleanup. These client checks can be bypassed and do not validate file contents, so exclude PDFs in the UI only if that is useful for usability; any authoritative acceptance policy must be enforced by Backend. Any future export must enforce its field allowlist server-side, not merely hide UI columns. The frontend records a small allowlisted set of authentication and request events through `src/lib/telemetry.ts`; today that function writes to the server console and has no observability pipeline destination. This signal is not an audit log and carries no JWT, PII, or form content.

**Implementation status (2026-10-01; checked against Backend `develop` `30d49ea1d56f735a124ae9260cafefff095e07b6`):** Backend issue #90 is closed as `NOT_PLANNED`, but its comments record partial completion and explicit exclusions. Magic-byte validation and the 10 MB cap are implemented; Exif/XMP/comments are removed from supported image formats when their structure is understood. PDFs and unrecognized image structures pass unchanged, and malware scanning is absent. Tier-2 auditing was explicitly deferred outside this delivery and remains absent, so the frontend must not promise who viewed a record. Export allowlisting is not applicable until an export endpoint exists; the stated future policy is an explicit server-side field projection. Issue closure does not mark the exclusions implemented. Treat PDF cleanup/malware and the deferred audit as release decisions under the security model; require explicit acceptance or a backend control before sign-off.

Considered Options:
- Let the frontend be the only gate on upload content and export fields — rejected: identical failure mode to trusting frontend-embedded Capabilities as authoritative (ADR-0005); a client-side-only gate becomes an actual bypass when anything calls the API directly.
- Have the frontend maintain its own audit log to cover the gap — rejected: an audit-of-record duplicated across two systems drifts, and Backend already receives the authenticated actor's identity on every request, so it's the natural single owner.
