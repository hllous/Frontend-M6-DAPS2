# Frontend security controls are defense-in-depth only; Backend validates and audits authoritatively

Evidence uploads and exports touch Tier 2 data (see the `Sensitivity Tier` term in `CONTEXT.md`) — a citizen's identity, inspector findings, violation/sanction detail — at a point where Backend's own endpoints (upload, audit, export) mostly don't exist yet ([#16](https://github.com/hllous/Frontend-M6-DAPS2/issues/16)). We chose not to let the frontend stand in as the authoritative gate in the meantime, extending the same posture [ADR-0005](0005-m6-backend-is-the-sole-authorization-authority.md) already took toward authorization: Backend independently validates every Evidence upload (real MIME type via magic bytes, size, EXIF stripped, malware-scanned) and is the sole audit-of-record, covering Tier 2 **reads** as well as writes. Frontend controls exist only to improve privacy and UX ahead of that authoritative check, never to replace it.

Concretely: the frontend re-encodes a camera-captured photo to JPEG client-side before upload (stripping EXIF as a side effect, and sidestepping inconsistent cross-browser HEIC decoding), and restricts a file-picker upload to JPEG/PNG at the UI layer — Backend still re-validates both paths from scratch. Any export feature enforces its field allowlist server-side, not by hiding UI columns. Frontend does emit its own security telemetry (CSP violation reports, `401`/`403` events, failed-auth redirects) to the observability pipeline ([#15](https://github.com/hllous/Frontend-M6-DAPS2/issues/15)), but this is defense-in-depth signal, not a substitute audit log, and it never carries a JWT, PII, or form content.

Considered Options:
- Let the frontend be the only gate on upload content and export fields, given Backend's real endpoints don't exist yet — rejected: identical failure mode to trusting frontend-embedded Capabilities as authoritative (ADR-0005); a client-side-only gate becomes an actual bypass the moment anything calls the API directly.
- Have the frontend maintain its own audit log to cover the gap while Backend's audit endpoints are unbuilt — rejected: an audit-of-record duplicated across two systems drifts, and Backend already receives the authenticated actor's identity on every request, so it's the natural single owner.
